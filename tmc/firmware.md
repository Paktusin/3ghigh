# TMC в прошивке: приём и выбор станции

Разбор по `fwmap/decomp/nav_core.c` и строкам `MMI3GApplication`
(MD5 `dbbfc29fb379ef11b5f6e28821871463`), 06.11.2026.

## Кто что делает

* **RDS демодулирует тюнер (радиоблок), а не навигация.** Навигация получает по
  шине MOST уже разобранные данные (строки `RDS/MOST`, `tmc_most_decoder_*`).
* Пакет от тюнера разбирает `FUN_0826badc` (около строки 44120 `nav_core.c`):
  u16 PI, два u8 (оба `< 0x40`: по разрядности это LTN и SID, 6 бит каждый —
  **догадка** по проверке `< 0x40`), байт типа `& 0x7f`:
  * `0` — сообщение TMC;
  * `1` — время (лог `TME PI=%04X utc=… local=…`);
  * `2` — пропускается;
  * прочее — `tmc_rdsmost GroupID 0x%02x unknown`.
  Пакет с PI = 0 отбрасывается.
* Таблицу локаций, события ALERT-C и показ на карте ведёт навигация (`DATA:
  get_next_msg_ccltn`, `DATA EUROAD cc… ltn…`).

## Навигация сама выбирает, какую таблицу слушать

`FUN_08267930` (строки 40750–40860) строит список «CC/LTN» для выбора станции:

1. **по стране**: для каждой таблицы реестра, у которой страна совпадает с
   текущей, — «`SEL: country(%d): add cc(%d) and ltn(%d)`»;
2. **по координатам**: если позиция внутри рамки таблицы (поля `+0x0C…+0x18`
   записи реестра — та самая рамка `BR`, см. `docs/formats/tmc.md`) **и** точка
   попадает в растр покрытия (`FUN_08267ac8(cc, ltn, pos) == 1`) — «`SEL:
   koord(…): add cc… ltn…`»;
3. **по кругу** вокруг позиции (`param_4`, радиус) — то же с расширенной рамкой.

Потом тюнеру уходит фильтр станций — `RDS TmcSelectionFilterArray entry …
PI=%04X, sid, CC, LTN, serv` и `RDS select station … PI SID LTN`.

Страна таблицы берётся из ISO-кода записи реестра (`+0x04`):
`FUN_0827cde4` переводит двух- или трёхбуквенный ISO во внутренний номер
страны. Значит, кипрская запись с ISO `CY` попадёт в выбор «по стране», если
номер страны совпадёт с тем, что навигация берёт из нашего `.xah`.

### Стратегии выбора и запасной путь (headless, 06.11)

Ghidra не создавала функций в `0x0825f000…0x08268000`. Их декомпилировал
headless-анализ диапазона (скрипт `fwmap/scripts/LitAnalyze.java`, 238 функций).

`FUN_0825f9a0` — цикл выбора станций. Он перебирает стратегии по строкам
`strategy …`:

| № | стратегия | откуда координата/страна |
|---|---|---|
| 0 | `curr position` | текущая позиция |
| 1 | `curr country` | текущая страна |
| 2 | `foresighted position` | точка впереди по маршруту |
| 3 | `foresighted country` | страна впереди по маршруту |
| 4 | `vicinity` | окрестность с радиусом |
| 5 | `no pos` | без позиции |

Для каждой стратегии список CC/LTN строит `FUN_08267b78` (обёртка над
`FUN_08267930`). Если список вышел **пустым**, есть запасной путь:
`FUN_08267bc0` берёт страну позиции и **её соседей** (`FUN_08278188`, перебор
соседних стран) и добавляет таблицы этих стран через выбор «по стране».

Дальше фильтр для источника (тюнера) собирается **только из записей этого
списка**: внутренний цикл (`FUN_0826002c` — следующий элемент) сверяет CC и LTN
каждой записи с маской источника (`0xff` — любое значение). Пустой список даёт
пустой фильтр. Стратегии 4 и 5 пропускают проверку страны, но берут записи из
того же списка.

**Вывод (по коду, 06.11):** на Кипре с заводским реестром список пуст во всех
стратегиях. Таблиц Кипра нет, а в запасном пути нужны таблицы соседей Кипра,
но в заводском `TMC` 3G есть только CZ, CH, IT, BE, LU, NL, DK, AT, GB, DE, ES,
SE, FR и NO. Навигация не попросит ни одну станцию. Значит:

* без своей кипрской записи в реестре и своей `.tlt` с рамкой и растром на
  Кипр наш передатчик слушать не будут;
* **отвергнуто:** проба передатчика «с немецким CC/LTN, стоя на Кипре».
  Германию не дают ни координаты, ни страна, ни соседи.

Не прочитано: держит ли тюнер последний фильтр, если ему пришёл пустой.
Для плана это неважно: на пустой фильтр опираться нельзя.

### Фильтр совпадения станции

`FUN_0826c288` проверяет станцию по записи фильтра: байт `+4` = CC (старшая
тетрада PI), `+5` = LTN, `+6` = SID. `0xff` в любом поле означает «любое».
Отсюда требование к передатчику: CC в PI, LTN и SID в группе 3A должны в точности
совпадать с кипрской записью реестра.

## Шифрование (TMCpro)

Классы `CAR` / `CRAR` (`getCaEncryptionMode`, `resolveCA`, `encGroupCA`,
`search_fictive_ltn_mapping`) — расшифровка платных служб. Режим «not
encrypted» существует. Наша служба — незашифрованная: в системной информации
группы 3A поле шифрования = 0. Ветку `fictive ltn` трогать не нужно.

## Bluetooth как канал TMC — нет (06.11)

Bluetooth в 3G High — отдельный блок Peiker (компонент `BTHS`; образы
`CoreApp.bin` / `HMI.bin` — заголовок U-Boot + gzip, распаковываются
`tail -c +65 | gunzip`). По путям исходников внутри `CoreApp` 0400 (09.08.2011):
модули `bths_hsm_qep` (громкая связь), `bths_ab` (телефонная книга),
`bths_sms` (SMS по AT-командам), `bths_simap` (SIM Access). Это голос,
контакты, SMS и SIM, произвольных данных для навигации там нет.

Драйверы TMC в навигации (`CFG_NAVCORE_TMC_DRV_*` в `ifs-root`, 5.8 DQ):
`RDS_MOST` (тюнер по MOST), `DAB_MOST`, `SDARS_SIRIUS`, `SDARS_XM`,
`RDS_INJECTION`. Драйвера от телефона или Bluetooth нет. SPP в главном блоке
используется только для загрузки ПО пульта (`RcCtrl_SwDlFsm: Request SPP for
SW download`). Значит, телефон → MMI по Bluetooth в TMC не попадёт без патча
прошивки. Bluetooth годится только как связь «телефон → передатчик».

`RDS_INJECTION` (06.11): это имя бита в маске
`CFG_NAVCORE_TMC_DRV_ACTIVE_MASK` (таблица имён `0x09a5b2cc`, 45-я запись
таблицы имён, связь номера записи с номером бита не проверена; значение маски — поле `+0x14` структуры конфигурации, вид
`startuptime`, `FUN_08e817f8`). В снятых с машины `config.nfm` (233 байта) TMC
нет, откуда берётся маска, не найдено. **Отвергнуто для нас:** даже если
включить этот драйвер, группы RDS кто-то должен подавать на самом головном
устройстве, а свои процессы на машине запускать нельзя. Остаётся эфир.

**Драйвера инъекции в сборке нет (06.11, по коду).** `FUN_082604fc`
(установка драйверов, перед ней `CTmcSourceList: calling tmc_drv_init()`)
берёт маску из поля `+0x14` конфигурации (0 → `-1`, то есть все) и
регистрирует ровно два драйвера через `FUN_08260410`: `"RDS_MOST"` и
`"SAT_Sirius"`. Больше ничего не регистрируется: `RDS_INJECTION`, `SDARS_XM` и
`DAB_MOST` — только имена в таблице конфигурации. В таблице установленных
драйверов максимум 8 мест. Включить инъекцию маской нельзя, нужен патч
бинарника. Единственный вход TMC на машине без патча — тюнер (RDS по MOST).

## Растр покрытия (06.11)

Цепочка `FUN_08267ac8 → FUN_08275f74 → FUN_08275e78(cc < 16, ltn < 64, …) →
FUN_08275ac8`. `FUN_08275e78` находит таблицу по CC/LTN, берёт u32BE по
`+0x30` её заголовка и зовёт читатель блока `BR` (`FUN_08275ac8`). Этот
читатель уже разобран и сверен на 707 тыс. точек: `docs/formats/tmc.md`,
блок `BR`. Растр нашей `.tlt` пишется по тем же правилам: клетка `(x − xmin)
>> 12`, строки снизу вверх, младший бит — левая клетка.

## Коды TMC на рёбрах XAC (06.11)

`xac_get_tmc_of_vector` — `FUN_082757ec`, имя из строки ассерта.

1. По `VID` находит блок, берёт список имён ведения вектора через
   `get_names_of_vector` (`FUN_082740bc`). Для каждого имени в параллельный
   массив кладётся его **вид**: старший байт группы 1 `ZF-NAMEN`.
2. Шапку `ZF-NAMEN` того же тайла читает `FUN_0827e4c8`: версия `+0x14` ≥ 2,
   `+0x40` u32 — число записей, `+0x44` — смещение таблицы от начала раздела,
   `+0x48` — длина в байтах.
3. Для имён **вида 4** берётся запись таблицы: `u32BE[номер имени]`, при
   условии `номер × 4 < длины`. Запись остаётся, если её бит направления
   (бит 3 байта 1) не равен запрошенному. При запросе «оба направления»
   (`param_3 == 2`) остаются все. Выход — до 10 кодов.

Маршрутизатор зовёт это при расширении (`FUN_08267190`, строка «`ROUTE: stop
expansion: get_tmc(…) failed`»). Значит, коды на рёбрах нужны и для объезда, и
для карты.

### Что в данных (сверка по всем 3777 тайлам завода)

**Имена вида 4 — это и есть коды TMC текстом**: `+A01+06406`, `+D01A21576`,
`+F32N05411`. Формат: `+`, CC одной hex-цифрой, LTN двумя десятичными, знак
вида, код локации пятью цифрами. В сортировке они встают первыми, потому что
`+` меньше букв.

Запись группы 3 (u32BE):

| байт | что |
|---|---|
| 0 | LTN |
| 1, старшая тетрада | CC |
| 1, младшая тетрада | вид; бит 3 — направление, его проверяет код |
| 2–3 | код локации, u16BE |

Знак в имени соответствует младшей тетраде, когда бит 3 = 1:

| знак | тетрада | записей |
|---|---|---|
| `A` | 1000 | 22 132 |
| `P` | 1001 | 189 271 |
| `N` | 1010 | 127 169 |
| `+` | 1011 | 272 573 |
| `-` | 1100 | 202 722 |
| `B` | 1101 | 24 746 |
| `C` | 1110 | 18 787 |
| `D` | 1111 | 15 451 |

Тетрада = 8 + номер знака в строке `APN+-BCD`. Исключений 27 на 872 тыс.
**Смысл знаков не установлен.** Догадка: `+`/`-` — направление по ALERT-C,
`P`/`N` — положительное и отрицательное смещение. Записи с битом 3 = 0 (примерно
половина) по числам выглядят как побитовая инверсия тетрады (0100 ↔ 1011,
0011 ↔ 1100), то есть встречное направление. Это **догадка по счёту**: имена
у этих записей наш `zfnamen.readSection` не раскрыл.

Проверки:

* число имён вида 4 = числу `+0x40` — **2816 из 2816** тайлов с таблицей;
* CC, LTN и код локации из записи совпали с текстом имени — **872 589** из
  разобранных имён;
* все номера имён вида 4 меньше `длина / 4` — **1 838 590 из 1 838 590**;
* длина равна `число × 4` у 2470 тайлов. У остальных 346 она больше на
  4…156 байт, и это ровно те тайлы, где имена вида 4 стоят не все первыми
  (2816 − 2470 = 346). Таблица адресуется номером имени, поэтому в ней есть
  пустые места;
* таблица лежит в самом конце раздела.

Заводские рамки: до **13 467** записей на тайл (`EJ211_HU0J_1.xac`), медиана
396; `ZF-NAMEN` до 125 212 байт.

**Для Кипра:** в наших `ZF-NAMEN` таблицы нет (`+0x40 = 0`). Нужно добавить
имена вида 4 `+2NN±LLLLL` в начало списка, записи группы 3 и ссылки на эти
имена в список имён ведения векторов (бит `0x20` описателя). Это правка XAC,
и до флешки её надо сверить с лимитами из `CLAUDE.md`.

## Что ещё прочитать в коде

* ~~поведение при пустом списке CC/LTN~~ — разобрано выше: пустой список даёт
  пустой фильтр, на него не опираемся;
* ~~растр покрытия~~ и ~~коды TMC на рёбрах~~ — разобраны выше;
* какие поля 3A/8A проверяет тюнер. **В этом бинаре этого нет:** RDS
  разбирает радиоблок, а навигация получает от него готовые `TMC::TMCData` и
  `TMC::TMCStations` по MOST (`CTMCTunerEventBroker`). Узнаётся только пробой
  в машине. Передатчик должен слать полный стандартный набор: 0A, 1A с ECC,
  3A с AID `0xCD46` (варианты 0 и 1), 8A;
* смысл знаков `A P N + - B C D` в именах TMC и записи с битом 3 = 0;
* соседи страны в запасном пути (`FUN_08278188`) — откуда берутся (для Кипра
  неважно, пока у соседей нет таблиц TMC);
* «страна» в выборе по стране — совпадает ли номер страны из ISO `CY`
  (`FUN_0827cde4`) с кодом Кипра `0x3a` в нашем `.xah`.
