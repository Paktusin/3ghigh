# Разбор навигационной базы MMI 3G / 3G+

Реверс-инжиниринг формата навигационных данных Audi/VW MMI 3G(P) (вендор Becker
Automotive). Всё получено чтением файлов; оригиналы никогда не изменялись.

Разобранный набор: **8R0060884KL, ECE 6.36.0, «EUR 2023»**, 22 ГБ.
Для сверки привлекался второй набор: 8R0060884HS, ROW 5.13.4, покрытие
Австралия и Новая Зеландия (VW Touareg RNS 850).

## Устройство набора

Три слоя, снаружи внутрь:

1. **Метаданные SWDL** — `config.nfm`, `DBInfo.txt`, `metainfo2.txt` плюс копии
   в каталогах релизов. Обычный текст. Здесь регион, версия, список вариантов
   головного устройства, к которым база применима.
2. **Манифест пакета** — `pkgdb/*.pkg` (текст) и по `*.conf` на каждый компонент
   с именем, размером, MD5 и контрольной суммой. Рядом `*.pkg.sig` — 128 байт,
   то есть подпись RSA-1024.
3. **Данные** — контейнеры FLDB и файлы ATLAS, GDB, PIT, XAR, ISO.

Код региона протянут через всё: `GDB_ECE`, `XAC_ECE`, `MMI3G_ECE_Hi_R_6_36_0.pkg`,
метка носителя `DB_ECE_PDU2`. В наборе ROW рынок и код компонентов расходятся:
`market=ROW`, а компоненты `_AN`. Есть и числовой идентификатор в `userflags`:
`region@1` для Европы, `region@10` для ROW.

## Что за что отвечает

Столбец «статус» отражает степень разобранности: **разобран** — формат описан
и читается кодом, **опознан** — назначение установлено, внутренности нет,
**не трогали** — руки не дошли.

### Общий индекс .xah

Обход находит 22 раздела и покрывает 1,6 МБ из 2,0 МБ, дальше обрывается.
Названия говорят сами за себя:

```
XACDB HEADER   STRING          BASIC NAME      LANGUAGE     COUNTRY
UNICODE INFO   UNICODE SORT    UNICODE COMBI   UNICODE CASE
ATTRIBUTE      ZF-TOKEN        ZF-LTMAP        ETA-KOSTEN   MAJOR ROAD
BUILD INFOS    XAC-STRUKTUR    XAC-STRUKTUR L1…L4
FE GRUPPEN     L3 GRUPPEN
```

Здесь стоит выделить три: `STRING` — тот самый всемирный словарь названий, где
рядом с CYPRUS лежат CALIFORNIA и COLOMBIA; `ETA-KOSTEN` — веса для расчёта
времени в пути, то есть часть маршрутизации; `MAJOR ROAD` — магистральная сеть.

#### Раздел COUNTRY — разобран

Реестр стран. Записи по 10 байт, начинаются со смещения 64 в разделе:

| Поле | Размер | Пример |
|---|---|---|
| внутренний код | 2 | `DM` |
| ISO 3166-1 alpha-2 | 2 | `DK` |
| ISO 3166-1 alpha-3 | 3 | `DNK` |
| код автомобильной регистрации | 3, дополнен нулями | `DK` |

Записей 216 — реестр всемирный и одинаков во всех региональных наборах: там же
штаты США, провинции Канады, страны Африки. Дорожные данные в европейском
наборе есть только у 46 из них, так что наличие записи покрытия не означает.

Таблица закрывает вопрос о внутренних кодах, которые до неё приходилось выводить
по топонимам: `MJ` — Мальта (MLT), `M1` — Черногория (MNE), `MB` — Молдова (MDA),
`KO` — Косово (XK), `DM` — Дания, `SW` — Швеция, `SP` — Испания, `AU` — Австрия,
`IR` — Ирландия. Отдельными записями идут Англия, Шотландия и Уэльс — с пустыми
кодами ISO и автомобильным `GB`.

**Кипр в реестре есть**: запись 112, внутренний код `CY`, `CY` / `CYP` / `CY`.
Турция — запись 108. То есть слот под страну заводить не нужно, он уже занят.

#### Раздел XAC-STRUKTUR — разобран

Реестр тайлов. Записи по 84 байта со смещения 24, в европейском наборе их
**3777** — ровно столько тайлов лежит в контейнерах XAC. Разбор в
`src/struktur.js`.

| Смещение | Значение |
|---|---|
| +0x00 | код тайла, 4 символа: две буквы страны и две цифры номера |
| +0x04, +0x08, +0x0C, +0x10 | накопленные размеры групп `VEKTORBLOCK` — границы уровней |
| +0x14, +0x18 | смещение и размер раздела `ZE-NAMEN` в файле тайла |
| +0x1C, +0x20 | то же для `ZE-NAMEN-MMI` |
| +0x24, +0x28 | то же для `HAUSNUMMERN`, нули если раздела нет |
| +0x2C, +0x30 | то же для `LOCAL POIS` |
| +0x3C, +0x40 | то же для `RASTERINFOS` |
| +0x44, +0x48 | ещё две границы групп `VEKTORBLOCK` |

Соответствие проверено на 151 тайле: все пять разделов совпали по смещению и
размеру в 100% случаев. Границы уровней проверяются иначе — например у тайла
`AB03` поля дают 26696, 42500, 44700, 45356, а это в точности суммы первых
одного, двух, трёх и четырёх блоков `VEKTORBLOCK`.

Назначение полей +0x34, +0x38, +0x4C и +0x50 не установлено — везде нули.

Практический вывод для добавления страны: тайл существует для устройства
постольку, поскольку он записан здесь. Запись описывает разделы своего файла,
поэтому новый тайл требует не только самого файла, но и строки в этом реестре.
Тайлов `CY**` в реестре нет.

Рядом лежат `XAC-STRUKTUR L1`…`L4`, по 166 212 байт каждый, — судя по всему
поуровневые таблицы с координатными рамками: в начале каждой читаются пары вида
20.076° в.д., 40.35° с.ш., что соответствует Албании, чьи тайлы идут в реестре
первыми. Не разобраны.

## Контейнер FLDB

Файлы XAC, LIT, TMC, LABEL. Числа little-endian.

| Смещение | Размер | Значение |
|---|---|---|
| 0x00 | u32 | 0x220 — начало области каталога |
| 0x08 | u32 | Unix-время сборки |
| 0x0C | u32 | количество файлов |
| 0x10 | u32 | 0x24 = 36, размер записи каталога |
| 0x14 | 4 б | сигнатура `FLDB` |
| 0x20 | | текстовый блок `!dbinfo0001 ... !enddbinfo` |
| 0x21C | | каталог |

Запись каталога, 36 байт: контрольная сумма (u32), смещение (u32), размер (u32),
имя (20 байт, дополнено нулями). Данные выровнены по 2048 байт; раскладка
детерминирована и воспроизводится побайтно, см. `src/repack.js`.

**Не разобрано:** алгоритм контрольной суммы. Проверены 77 вариантов (все
стандартные полиномы CRC32 во всех комбинациях init/reflect/xorout, Adler-32,
Fletcher-32, FNV, djb2, sdbm, Jenkins, суммы и XOR по словам), по сырым и по
выровненным данным — совпадений нет. То же поле встречается в хвосте каталога,
как `checkcrc` в `.conf` и как `fdefcrc` в `.pkg`. MD5 в `.conf` при этом обычный
и совпадает точно.

## Дорожный тайл .xac

Имена внутри контейнера: `<ПРЕФИКС>_<CC><TT>_<n>.xac`, где CC — внутренний код
страны, TT — тайл. Коды локальны для базы: в европейском наборе `AU` — Австрия,
в наборе AN `AT` — Австралия.

### Разделы

Сплошная последовательность: 16 байт имени, u32 BE длина полезной части,
полезная часть. Полный размер раздела равен длине плюс 20. Обход покрывает файл
ровно до конца. Встречаются `XAC HEADER`, `ZF-NAMEN`, `VEKTORBLOCK`, `ZE-NAMEN`,
`ZE-NAMEN-MMI`, `HAUSNUMMERN`, `LOCAL POIS`, `RASTERINFOS`.

### Заголовок VEKTORBLOCK

Смещения от начала раздела:

| Смещение | Значение |
|---|---|
| 0x14 | u16 BE — версия структуры: 3, 4 или 5 |
| 0x18 | 4 x i32 BE — границы: xmin, ymin, xmax, ymax |
| 0x28 | 2 x i32 BE — опорная точка блока |

Версия коррелирует с масштабом: медианный охват 2,5 км у v3, 3,5 км у v4,
24 км у v5.

### Проекция

Равнопромежуточная цилиндрическая:

```
долгота = X / 72000
широта  = Y / (40000000 / 360)     // 111111.111… — метры на градус
```

Y — метры по меридиану для сферы окружностью 40 000 км. X — угловая величина,
20 единиц на угловую секунду. Выведено по микрогосударствам с точно известными
координатами, проверено на Ватикане с точностью около 100 метров.

Побочная находка: у Ватикана два тайла — `VA01` это собственно Ватикан,
`VA00` — Кастель-Гандольфо, экстерриториальное владение Святого Престола.

### Записи, версии 3 и 4

Запись переменной длины. В хвосте лежит самоиндекс — слово u16 BE, равное
смещению записи, делённому на 2. Координаты хранятся дельтами от опорной точки
блока. Признак расширенной записи — старший бит первого байта.

```
обычная    : dx = u16BE(p)   - 0x4000     dy = u16BE(p+2) - 0x8000
расширенная: dx = i16BE(p+2)              dy = i16BE(p+4)
```

Связи между узлами: внутри записи слово с двумя старшими битами (`0xCxxx`)
ссылается на узел по идентификатору `w & 0x3FFF`. Засчитываются только взаимные
ссылки — у цели должно найтись слово `0x4000 | (q/2)`.

**Версия 3.** Одна сплошная секция записей с 0x60. Слово по смещению 0x4E — её
конец; ноль означает «до конца блока», ненулевое отделяет вторую секцию.

**Версия 4.** Блок нарезан на под-блоки. Каждый начинается с рамки — четырёх
u32 BE (xmin, ymin, xmax, ymax) внутри границ блока, затем идут записи того же
формата. Опорная точка при этом общая, блочная, а не своя у каждого под-блока:
с опорой на угол рамки попадает 50% записей, на центр 30%, на опору блока 100%.
Конец данных берётся из u32 по смещению 0x60.

### Версия 5

Под-блоки размечаются рамками так же, как в v4. Координаты кодируются **теми же
биасами, что в v3 и v4, и тоже от опорной точки блока**:

```
x = origin_x + u16BE(p)   - 0x4000
y = origin_y + u16BE(p+2) - 0x8000
```

То есть кодирование координат едино для всех трёх версий; отличается только
разметка. Механизма самоиндекса в v5 нет (2 подходящих слова из 119), и записи
не фиксированной длины — перебор длин 4…16 даёт максимум 44,8%. Поэтому границы
записей не восстанавливаются, а координаты выбираются сканированием с проверкой
по рамке под-блока: рамка занимает считаные километры, вероятность случайного
попадания пары в неё порядка 1e-4 на позицию, ложных срабатываний практически
не бывает. Достижимость проверена: 147/148, 165/165 и 190/190 под-блоков лежат
в пределах 16-битной дельты от опоры блока.

Следствие: из v5 извлекаются точки, но не топология — связи `0xCxxx` без разметки
записей не привязать. Рёбра в выгрузке дают только блоки v3 и v4.

Заблуждение, которого стоит избегать: диапазон дельты нужно считать не против
границ блока, а против фактического размещения данных. Границы блока Мальты шире
достижимого диапазона, из-за чего v5 сперва была ошибочно признана
недекодируемой.

## TMC

Реестр таблиц локаций лежит в `EJ211_global.tlt`: метка `TMC-LOC-TABLE OV`,
u16 BE число записей по 0x1A, записи по 36 байт с 0x20.

| Смещение | Значение |
|---|---|
| +0x04 | ISO-код страны, 2 байта |
| +0x06 | u8 ECC, расширенный код страны RDS |
| +0x07 | u8 код страны RDS |
| +0x08 | u8 LTN, номер таблицы локаций |
| +0x1C | код языка, 2 байта |

Имена файлов таблиц: `<ПРЕФИКС>_<код RDS>_<LTN>.tlt`. В европейском наборе
27 таблиц на 22 страны, у России шесть.

## Покрытие

Европейский набор: 46 кодов стран с дорожными данными при 216 записях в реестре
`COUNTRY`, и 45 справочников названий `.ort`. Расхождение между 46 и 45
объясняется Черногорией (`M1`) — дорожные данные есть, а её топонимы лежат в
файле Сербии, наследие единого государства; в файле Сербии находятся Улцинь и
Тиват.

Кипра в данных нет: ни тайлов, ни городов, ни справочника. Поиск по всем 22 ГБ
не дал ни одного настоящего совпадения — LIMASSOL, LEMESOS, LARNAKA, PAPHOS,
KYRENIA отсутствуют. То, что находится, посторонее: LEFKOSIA и AMMOCHOSTOS —
улицы материковой Греции, названные в честь кипрских городов; NICOSIA — городок
на Сицилии; единственный LIMASSOL — бар в Ростове-на-Дону из базы точек интереса.

При этом сам Кипр зарегистрирован в реестре `COUNTRY` под кодом `CY`, а строка
CYPRUS есть в словаре `STRING`. Ни то ни другое покрытия не означает: реестр и
словарь всемирные и одинаковы во всех региональных наборах.

## Где лежат данные

Сам навигационный набор в репозиторий не входит — это 22 ГБ, и он неизменен,
так что версионировать в нём нечего. Целостность проверяется без git: в каждом
`.conf` лежит MD5 своего бинарника.

Скрипты ищут каталог набора сами — тот, внутри которого есть `pkgdb`. Порядок:
явный аргумент, переменная окружения `MMI3G_MAPS`, каталог `maps` рядом с
репозиторием, корень репозитория, текущий каталог. Раскладка по умолчанию:

```
maps/           навигационный набор (в git не входит)
  pkgdb/
  metainfo2.txt
  ...
src/            скрипты
out/            выгрузки GeoJSON (пересоздаются, в git не входят)
```

## Инструменты

```
src/dataset.js    поиск каталога набора
src/struktur.js   реестр тайлов XAC-STRUKTUR
src/fldb.js       контейнер FLDB: разбор, список, извлечение
src/repack.js     пересборка контейнера, проверка round-trip
src/coverage.js   сводка по набору: регион, версия, страны
src/probe.js      покрытие по неполному файлу — хватает первых ~250 КБ
src/countries.js  таблица стран европейского набора
src/tmc.js        реестр таблиц локаций TMC
src/xac.js        разделы тайла, заголовки блоков, проекция
src/nodes.js      узлы и связи из блоков v3/v4/v5, выгрузка в GeoJSON
src/harvest.js    поиск абсолютных координат перебором
src/gjcheck.js    проверка GeoJSON и рисунок сети в терминале
```

Пример:

```
node src/coverage.js                       # набор найдётся сам
node src/coverage.js /путь/к/другому/набору
node src/nodes.js maps/pkgdb/.../EJ211_MO00_1.xac out/MO00.geojson
node src/gjcheck.js out/MO00.geojson
```

Результат проверяется перетаскиванием `.geojson` на geojson.io.
