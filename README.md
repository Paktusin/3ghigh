# Разбор навигационной базы MMI 3G / 3G+

Реверс-инжиниринг формата навигационных данных Audi/VW MMI 3G(P) (вендор Becker
Automotive). Всё получено чтением файлов; оригиналы никогда не изменялись.

Разобранный набор: **8R0060884KL, ECE 6.36.0, «EUR 2023»**, 22 ГБ.
Для сверки привлекался второй набор: 8R0060884HS, ROW 5.13.4, покрытие
Австралия и Новая Зеландия (VW Touareg RNS 850).

## Состояние

| Что | Статус |
|---|---|
| Контейнер FLDB | разобран, пересобирается побайтно |
| Контрольные суммы | `CheckSum`, `check=qa`, сумма каталога FLDB опознаны и проверены сплошь; `checkcrc`/`fdefcrc` — нет, но на устройстве сверка базы выключена (`database checking is not enabled`) |
| Проекция | выведена и проверена на карте |
| Разделы .xac | разобраны |
| Блоки v3 | 20 из 20; корпус расширен до **29 045 записей** из 247 блоков. Структура слов середины: повторяющаяся группа `[связь 0xCxxx][0x8xxx][0x8xxx][мелкое]`, в конце терминаторы `0x4`/`0x0`. Слова `0x8xxx` — **данные, не ссылки** (разрешаются в узел 5.4% при 7.7% случайных). **Первое слово — класс дороги**: вскрыто сопоставлением с OSM, чем важнее дорога, тем меньше значение (primary 2–4, secondary 51–54, residential ~152, track 168). Второе слово и мелкое слово группы не вскрыты |
| Блоки v4 | 9 из 9, 100% байт |
| Блоки v5 | **читаются и собираются обратно**. Шапка разобрана поле за полем: `0x16` — это `cos(широты)` в формате 1.15 (сходится на 1286 блоках из 1288 и подтверждает проекцию с другого конца), `0x30` и `0x32` — счёт векторов и узлов по таблице (сошлись двумя способами на 67 блоках из 67), `0x3a` — код страны. Заголовки под-блоков по 22 байта стоят по всей области, признак «две пары i32 внутри рамки» отличает их безошибочно: 12 722 из 12 722 при нуле ложных на 463 543 записях. **Отвергнуто**: слово `0x4000` в списке — не обратная ссылка, а чаще всего компактная координата с `dx ≥ 0`; начала узлов надо брать из таблицы (94.5 % против 62.2 %). **Обратный проход** (`src/xacwrite.js`): 954 блока из 963 собираются байт в байт, 70.5 % байт — из разобранных значений. **Генерация** (`buildBlock`): граф превращается в блок, и `xacvec.blockEdges` возвращает из него те же рёбра. Осталось: назначение полей `0x3e`, `0x44`, `0x48`, содержимое хвостовой области и код страны для Кипра |
| Общий растр .ras, NACHBARN, XAC HEADER | разобраны |
| ZF-NAMEN и ZF-TOKEN | **вскрыты**. Сжатие снято с прошивки (`FUN_08279074`): код 1 — литерал, 2 — конец, 3 — серия, ≥6 — токен номер «код−6» из таблицы `ZF-TOKEN`, а байт `0x02` внутри токена кончает имя. На 417 разделах (161 749 имён) **ни одного сбоя разбора**; ключи группы 0 сходятся с раскрытыми именами на 98.08 %. Раскладка раздела проверена на 536 разделах, правило «ключей ceil(имён/16)» — на 417 из 417. **Обратный проход** (`src/zfnamen.js`): имя сжимается в те же байты у 86.46 %, раздел собирается байт в байт у 164 из 245. Открыто: у 172 разделов имён в потоке меньше, чем записей группы 1 — см. [docs/formats/zf.md](docs/formats/zf.md) |
| Зависание на 28% | **разгадано и вылечено**: после частичной установки пропадает `/HBpersistence/navi/db/acios_db.ini`; кладём его обратно (`tools/write_fixacios.sh`) — навигация поднимается. Данные ни при чём |
| Перенос тайлов на устройство | ставится без ошибок. Прежний вывод «виснет на любом сдвиге рамок тайла» **снят**: все те сборки были частичными установками и падали на пропавшем описателе, а не на данных |
| Сумма в каталоге FLDB | **взломана** (ndr FUN_0807a0b8): CRC-шаг 0x04C11DB7 + сложение, 0xC7; `relocate.js` пересчитывает |
| Сумма блока CIFF | тот же алгоритм; в тайлах/.xah не используется, только в прочих данных |
| GDB | шапка, 12 уровней, сетка кластеров L0 (`slot=cy·W+cx`), 19-байтные тайлы, заголовок блоба, поток элементов, кодирование точек и **реестр S1/S2** — разобрано и пишется (`src/gdb.js`, `src/gdbwrite.js`, `src/gdbroads.js`). **Каталог уровней разобран** (`FUN_08cb20f0`): в шапке 32 пары «смещение, размер», из них заполнены 12; у каждого уровня своя шапка с размером ячейки и диапазоном масштабов. **Сетка разобрана на всех двенадцати уровнях**: в старших разрядах ключа кластера записан номер уровня (`x0 = уровень<<12`, `y0 = 0x8000`; у L0 нули, у L1 `0x8000/0`) — совпало у 3309 кластеров из 3309, и `slot = cy·W + cx` сходится теперь по всей таблице (L0 1780/1782, L1 1809/1811, L11 78/78). Калибровка «градусы ↔ ячейка» стала поуровневой, урезанный том сохраняет все уровни (13,5 МБ вместо 3,6 ГБ). **Том собирается с нуля** (`src/gdbgen.js`, тесты `src/gdb.test.js`, `src/gdbgen.test.js`, `src/gdbstrip.test.js`): заголовок блоба — 10 байт, а не 16 (прежнее `m_size_daten` — ошибка чтения); первый элемент тайла — служебная рамка в 26 байт; кластер = `размер/19` записей **в порядке Мортона**, поисковой таблицы на диске нет; таблица кластеров начинается на **+1163** у всех 12 уровней, а её ширина считается по рамке `W = ceil((x1−x0)/(cellX·2^potX))` и сходится на всех 12; пустой тайл собирается байт в байт как оригинальный. Осталось: единица координат в тайлах грубых уровней (у L1 тайл 126 976 мировых единиц — вдвое больше u16, поэтому дороги пишутся только в L0), содержимое каталога блобов (44 747 пар @874 970, 318 МБ), бит-упакованный вариант потока точек, секция S3; собранный том на машине ещё не ставился |
| Инициализация NDL | автомат разобран; `end: NDL Initialisation` печатается только из состояния 3 и оттуда — всегда, значит зависание сидит до него, в состоянии 0, 1 или 2. Какое именно — по журналу неразличимо: эти сообщения идут в отключённый канал |
| LIT…LIT4 и PIT | **база точек интереса**, один контейнер с магией `Lit\x02`. Каталог разобран: у LIT 245 518 блоков, у PIT 717 (`src/lit.js`); найдено, что **тома склеивались неверно** — файл добит нулями до кратности 2048, швы выводятся из каталога (`fixSeams`). Машина грамматики (`src/litvm.js`) сверена с `FUN_08cd0798` и доходит до точной границы у **всех 245 518 блоков LIT и всех 717 PIT**. **Дерево POI читается**: узел это две рамки-половины с делением длинной стороны и до четырёх ссылок (26 106 из 26 106 ведут в блоки с узлами или тайлами). **Обратный проход** (`src/litenc.js`): байты собираются заново из значений — вся PIT 717/717 и 1932 блока LIT из 2000, побайтово, без дыр и нахлёстов. **Имена**: сжатие воспроизводится байт в байт на 36 193 именах; **словарь строится** (`litdict.build`, кодирование пар байт) — число кодов совпадает с оригиналом во всех проверенных блоках, объём 103.2 % от него. Осталось до генерации: раскладка блоков и номера в ссылках дерева, сборка каталога и контейнера, генерация PIT, засев координат в блоках геометрии. Подробности в [docs/formats/lit.md](docs/formats/lit.md) |
| ATLAS (CTY/TER) | **контейнерный формат разобран**: разделы с именем и размером, сигнатура контейнера `0123456789abcdef…`, тип содержимого строкой. `TER` — 11 051 контейнер `SoarTerrain`, `CTY` — 2539 `Map` и один `Root`. Содержимое контейнеров не разбиралось. Прежде: опознаны магии (`Lit\x02`+`HBIS`; `\x06HEADER`+`Orion`+`Atlas`), не разбирались |

Разбираются все 40 векторных блоков во всех восьми проверенных тайлах. Узлов
после включения v5: Мальта 39 939, Андорра 15 531, Лихтенштейн 8 892,
Сан-Марино 6 816, Монако 1 760.

Проверка результата глазами: выгрузка Мальты в ASCII воспроизводит очертания
архипелага — Гозо на северо-западе, Комино между островами, главный остров
с уплотнением на юго-востоке у Валлетты.
