# TMC

## TMC

Реестр таблиц локаций лежит в `EJ211_global.tlt`: метка `TMC-LOC-TABLE OV`,
u16 BE число записей по 0x1A, записи по 36 байт с 0x20.

| Смещение | Значение |
|---|---|
| +0x04 | ISO-код страны, 2 байта |
| +0x06 | u8 ECC, расширенный код страны RDS |
| +0x07 | u8 код страны RDS |
| +0x08 | u8 LTN, номер таблицы локаций |
| +0x1C | код языка, 2 байта |

Имена файлов таблиц: `<ПРЕФИКС>_<код RDS>_<LTN>.tlt`. В европейском наборе
27 таблиц на 22 страны, у России шесть.

## TMC для Кипра (19.10)

* В заводском реестре (`EJ211_global.tlt`) 27 таблиц на 22 страны — **Кипра
  нет**. Публичной таблицы локаций Кипра (ISO 14819-3, CID/TABCD) и службы
  RDS-TMC на Кипре поиск не нашёл (OSM wiki «TMC/Location Code List» Кипра не
  знает). Значит дорожных сообщений по FM на Кипре MMI не получит, какую бы
  таблицу мы ни собрали; онлайн-трафика у MMI 3G нет.
* Компонент `TMC` (6,7 МБ) кладём заводским: таблицы читает фаза 2
  инициализации DBM (docs/device.md), без компонента — риск для старта, а
  выигрыш в объёме мал.
* Собирать свою таблицу имеет смысл, только если появится служба TMC на Кипре.

### Что внутри компонента `TMC` (MMI3G, 19.10)

Контейнер FLDB `kN221EUx01t01.db`, 15 записей: реестр `EJ211_global.tlt` и 14
таблиц локаций `EJ211_<CC>_<LTN>.tlt` (CZ, CH, IT, BE, LU, NL, DK, AT, GB, DE,
ES, SE, FR, NO; «27 таблиц на 22 страны» выше — это `TMC3GP` для 3G+).
Строка реестра: ISO, ECC, CC (страновой код RDS из PI), LTN (номер таблицы),
язык. Таблица начинается меткой `TMC-LOC-TABLE BR` и строкой
`!14!TLT 7_1 with 1 raster!41!`, дальше — сжатые двоичные данные (не разобраны):
по смыслу это коды локаций ALERT-C с привязкой к дорогам карты.

**Частот там нет.** Станцию с TMC приёмник находит сам: страна и таблица
приходят в RDS (CC в коде PI, ECC, LTN в системной информации TMC), и MMI ищет
в реестре таблицу с такими CC/ECC/LTN. `TMCConfig.dat` (в образ не кладём) —
строки вида `4;2;64;15;30;62;15;32;62;` и `SEK=1`; по виду — настройки служб по
странам/таблицам, `SEK` — похоже, ключ шифрованных служб (TMCpro). Догадка, не
разбиралось.

Если на Кипре появится служба: нужна её таблица локаций (от оператора) и своя
`.tlt` с привязкой к нашим дорогам XAC — формат тела `.tlt` ещё не разобран.

### Блоки

Файл — цепочка блоков встык до конца файла: метка 16 байт, u32BE размер
(**считается от `+0x14`**, то есть u32 0 на `+0x14` входит в блок), данные с
`+0x18`. В каждой таблице четыре блока: `BR`, `"  "`, `XY` и последним
`COMMENT` (текст `!14!…!41!`: имя файла, дата сборки, исходный `.lcl`).
Первые три:

| Блок | Код в `dbm_tlt_ov_get_chunksize` (`FUN_08ec54d8`) | Что внутри |
|---|---|---|
| `BR` | 8 | рамка + битовый растр покрытия (`!14!TLT 7_1 with 1 raster!41!`) |
| `"  "` | 2 | записи локаций (`tmc_loc_table_array`) |
| `XY` | 4 | координаты локаций (`tlt_xy_table_array`) |

У всех трёх одинаковый подзаголовок с `+0x18`: байт версии, байт, **CC**,
**LTN** (`10 01 07 01` у `EJ211_07_01`).

**Координаты — в единицах XAC** (`X/72000`, `Y/111111`). Проверено на
`EJ211_07_01`: рамка `BR00` 5,53…6,72° в. д. × 49,32…50,32° с. ш., опорная
точка `XY00` 6,09/49,67 — Люксембург (CC 7, LTN 1).

### Запись локации — `FUN_0827659c` (прочитано в коде)

Вход — данные блока `"  "` с `+0x18` и код локации; выход — структура 0x28
байт. Ветвление по байту версии:

* **0x10…0x1F** (так у всех заводских): u32BE по `+4` — смещение `BS00`
  (у `07_01`: `0x28`, сходится с меткой на `0x118`). `BS00` — битовый поток:
  таблица диапазонов по 8 байт (u16 первый `loc>>4`, u16 последний, u32
  битовое смещение), бинарный поиск, дальше чтение битов (`FUN_08276d04` —
  инициализация, `FUN_08276d0c` — чтение). Разобрано целиком — см. ниже
  «`BS00`».
* **5** — простая байтовая раскладка, без битового потока:
  `+2` CC, `+3` LTN, u16BE `+4` — индекс в словах; индекс: u16 первый
  `loc>>4`, u16 число, u16 указатели (×8 байт); по указателю — 16 u16 смещений
  по `loc & 0xF`; запись: байт типа (`& 0x7F`, бит 7 — флаг), байт флагов
  полей, дальше поля varint (7 бит на байт, старший бит — продолжение);
  ссылочные поля хранятся разностью с кодом локации.

Выходная структура (поле → смещение) ложится на запись ALERT-C (ISO 14819-3):
`+0` CC, `+1` LTN, `+2` код, `+4` тип, `+6` и `+8` два кода-соседа, `+0xA`,
`+0xC` ещё две ссылки, `+0x10…+0x1C` четыре u32, `+0x20`, `+0x24` два
значения с масштабом. **Назначение полей — догадка по ISO**
(соседи = отрицательное/положительное смещение, ссылки = линия/область,
u32 = id имён, последние два — координаты); в коде пока прочитано только
«что откуда берётся».

**Отвергнуто: писать свою таблицу версией 5.** Версию 5 понимают
`FUN_0827659c` (запись) и `FUN_08277110` (имя), но координаты
`FUN_08276e2c` начинаются с `if (*p < 6) return -1`, и `RS00`
(`FUN_0827735c`) тоже только `0x10…0x1F`. Версия 5 — старая ветка, писать
надо `0x10`.

### Подзаголовок версии 0x10 (с `+0x18` блока)

| Смещение | Что | Кто читает |
|---|---|---|
| `+0` | u8 версия `0x10` | все |
| `+2`, `+3` | CC, LTN | |
| `+4` | u32BE → `BS00`, записи | `FUN_0827659c` |
| `+8` | u32BE → имена, магия `SP01` или `SP02` | `FUN_08277110` |
| `+0xC` | u32BE, назначение не установлено (`0x24` в `"  "`, `0x14` в `XY`) | — |
| `+0x10` | u32BE → `XY00` | `FUN_08276e2c` |
| `+0x14` | u32BE → `RS00` (0 у всех заводских) | `FUN_0827735c` |

В блоке `"  "` у `EJ211_07_01` `+0x10 = 0`, и координаты берутся из блока
`XY` (`xac_get_tmc_loc_infoxy` пробует сначала основной блок, потом `XY`).

### `XY00` — разобран и проверен (`src/tlt.js`)

| Смещение | Что |
|---|---|
| `+0` | `XY00` |
| `+4` | u16BE первый код локации |
| `+6` | u16BE охват кодов |
| `+8`, `+0xC` | i32BE опорные X, Y (единицы XAC, **со знаком**) |
| `+0x12` | u16BE число диапазонов |
| `+0x14` | диапазоны по 6 байт: u16BE начало (от первого кода), u8 число локаций, u24 (байт старший, затем u16BE) смещение потока от `XY00` |

Поток битов MSB-first. На локацию **две точки** (начало, конец; у точечной
локации они равны), всего `2 × число` точек в диапазоне, дельты накопительно
от опорной точки. Точка: бит «изменилась»; если 1 — число X, число Y. Число:
пока бит 1 — `v = v·256 + целый байт`; затем пока бит 1 — `v = 2v + бит`;
если `v ≠ 0` — бит знака (1 — минус).

**Проверка с двух концов:** все 14 таблиц ложатся точно в свои страны —
LU 5,74…6,51 × 49,45…50,18 (3914 локаций), GB −8,10…1,75 × 49,91…60,49 (с
Северной Ирландией), ES −16,74…3,19 × 27,76…43,73 (с Канарами), NO до 71,2°
с. ш. Ошибка в одном бите разнесла бы координаты. Чтение X без знака давало
у GB и ES долготы 13 888…59 654 — X знаковый.

Обёртки `xaclib` (`nav_core.c`, `FUN_08277504`/`FUN_082775e4`/`FUN_08277748`):
`xac_get_tmc_loc_name`, `xac_get_tmc_loc_infoxy`, `xac_get_tmc_loc_all`.
Получение блоков по (CC, LTN): `FUN_08eb3cbc` → `"  "`, `FUN_08eb3cd0` → `XY`

Соответствие по коду обёрток, тела трёх функций не читались.

### Привязка к дорогам — через векторы XAC, не через таблицу

Блока `TMC-LOC-TABLE CA` (есть в диспетчерской таблице прошивки) нет **ни в
`TMC`, ни в `TMC3GP`**. Привязка иная: `xac_get_tmc_of_vector(VID)`
(`FUN_082757ec`, `xac_tmc.cpp`) обходит атрибуты вектора, берёт записи вида 4
и по их индексу (`& маска`, ×4) читает u32BE коды TMC из массива тайла; бит
`0x08` второго байта — направление (сравнивается с запрошенным). Маршрутизатор
это использует: `"keine TMC-Codes"`, `"ROUTE: stop expansion: get_tmc(…)
failed"`.

**Следствие:** своя таблица Кипра без кодов TMC на рёбрах нашего XAC
сообщения покажет списком, но на карту и в маршрут они не лягут (догадка по
коду — на машине не проверено). Где в тайле массив кодов (`FUN_082759d4`) и
какой это атрибут в `ATTRIBUTE` — не разобрано.

### `BS00` — записи локаций, разобран и проверен (`src/tlt.js`, `records`)

Читатель битов `FUN_08e85b40`: состояние `[0]` база, `[4]` позиция в битах,
`n` бит MSB-first. База потока — `BS00 + 10`.

| Смещение | Что | У заводских |
|---|---|---|
| `+0` | `BS00` | |
| `+4` | u8 F, флаги | всегда 3 |
| `+5` | u8 N, разрядность id имён | 11…16 |
| `+6` | u8 C, разрядность полей `x20`/`x24` | 14…19 |
| `+7` | u8 G, разрядность длины группы | всегда 12 |
| `+0xA` | u16BE число диапазонов | 64…80 |
| `+0xC` | диапазоны по 8 байт: u16BE первая группа, u16BE последняя, u32BE битовое смещение от базы | |

**Группа** — 16 кодов (`loc >> 4`). Бит 0 — группа пуста. Бит 1 — дальше G
бит длины группы (в битах, после заголовка), маска полей — `(F&1)+4` = 5 бит
при `F&2` (ветка без `F&2` в коде есть, ширина в декомпиляции потеряна; у
заводских не встречается). Дальше слоты 0…15 до конца группы.

**Слот:** бит присутствия; если 1 — запись:

| Поле | Кодирование | Значение |
|---|---|---|
| `flag` (`+0xE`) | старший из 2 бит | не установлено |
| `type` (`+4`) | младший из тех 2 бит: 1 — как у прошлой записи группы, 0 — 7 бит | тип локации |
| `neg` (`+6`) | 2 бита: 0 — нет, 1 — `loc−1`, 2 — 15 бит, 3 — `0x8000 \| 15 бит` | отрицательное смещение |
| `pos` (`+8`) | то же, 1 — `loc+1` | положительное смещение |
| `area` (`+0xC`), если маска & 16 | 2 бита: 0 — нет, 1 — как у прошлой, 2/3 — 15 бит (3 — с `0x8000`) | ссылка на область |
| `line` (`+0xA`), если маска & 8 | то же | ссылка на линию |
| `n10` (`+0x10`) | 2 бита: 0 — нет, 1 — как у прошлой, 2 — N−1 бит, 3 — `1<<(N−1) \| N−1 бит` | номер дороги |
| `n14`, если маска & 4 | бит + N бит | название дороги |
| `n18` | бит + N бит | первое имя |
| `n1c`, если маска & 2 | бит + N бит | второе имя |
| `x20`, `x24`, если маска & 1 | бит + C бит каждое | не установлено |

«Как у прошлой» — внутри группы, в начале группы сбрасывается в 0.

**Проверка с двух концов:**

* длина каждой группы из заголовка совпала с разобранным до бита — **23 544
  группы, 334 993 записи, все 14 таблиц, ни одного расхождения**;
* ни одной битой ссылки `neg`/`pos`/`area`/`line` (≈ 600 тыс.), при чтении
  16-битного кода целиком — то есть код 3 (`0x8000 | …`) — это просто коды
  ≥ 0x8000, не флаг (у LU коды до 60 644);
* число `neg` во всех таблицах равно числу `pos` — цепочки замкнуты;
* смысл полей виден на данных LU: точки 103 → 104 → 105 связаны `neg`/`pos`,
  у всех `line = 108`, а 108 — запись-линия (type 22) с `n10 = 48`; у точек
  `area = 10`, у области 10 — `area = 1`.

Имена полей `n10…n1c` установлены по `SP02` — см. ниже. Соответствие 7-битного `type` классам ISO 14819-3 — не
установлено. Блок `XY` покрывает не те же коды: у LU 3914 точек `XY` на 1625
записей (2449 кодов `XY` без записи — промежутки диапазонов, 160 записей без
`XY` — видимо, области).

### `SP02` — имена, разобран и проверен (`src/tlt.js`, `names`)

Читатель `FUN_08277110`, пропуск имени `FUN_08278fc8`, разворот
`FUN_08279074` — **то же сжатие `u_dekomprimieren`, что у `ZF-NAMEN`**
(`src/zfnamen.js` — `decode`/`encode` годятся как есть).

| Смещение | Что |
|---|---|
| `+0` | `SP01` или `SP02` (у всех заводских `SP02`) |
| `+4` | u32BE число имён |
| `+8` | u32BE размер словаря фрагментов (2500 = 250 × 10) |
| `+0xC` | словарь: записи по 10 байт до NUL, фрагмент № = код − 6 |
| `+0xC + словарь` | индекс: u16BE на каждые 16 имён, ×8 — смещение группы от конца индекса |
| дальше | имена |

У `SP02` после каждого имени — байт длины общей приставки со следующим
именем (в начале группы — 0). Имена отсортированы, кодировка Latin-1.
**id имени в записи считается с 1, 0 — нет имени.**

**Проверка с двух концов:**

* все 14 таблиц, 220 тыс. имён: всё разворачивается, пустых нет, порядок
  строго возрастающий (подтверждает приставки);
* **число разных id в `BS00` в каждой таблице ровно равно числу имён** и ни
  один id не выходит за край — каждое имя использовано, отсчёт с 1 верен;
* на LU смысл полей виден по географии: 1 — `Europe`, 10 — `Luxembourg`,
  12 — `Allemagne`; 108 — `B40` «Voie express», от «Esch Raemerich» до
  «Frontière France», её точки 103–105 — Raemerich, Belval-Université,
  Belval-Gare (реальные развязки B40); 112 — `CR108` Steinfort — Eischen.

Отвергнуто: id с 0 — давало «Everlange» стране и «B4A» вместо `B40`.

### `BR00` — покрытие, разобран и проверен

Читатель — `FUN_08275ac8` (магия `BR00` по `DAT_08275e4c`). Блок `BR`:
подзаголовок версии 0x10, u32BE на `+0x18` → `BR00`.

| Смещение | Что |
|---|---|
| `+0` | `BR00` (выровнен на 4) |
| `+7` | u8 число входов (у заводских 1) |
| `+8` | u32BE смещения входов от `BR00` |

Вход: байт (старший полубайт — число 6-байтовых строк после прямоугольников,
младший — длина хвоста после строк; у заводских 0), байт, u16BE число
прямоугольников, прямоугольники по 20 байт: i32BE `xmin, ymin, xmax, ymax`
(единицы XAC) и u32BE вид. Вид 1 — прямоугольник покрыт целиком; **вид ≥ 8 —
смещение растра от `BR00`**: u8 сдвиг X, u8 сдвиг Y, u16BE байт на строку,
биты строками снизу вверх (от `ymin`), в байте младший бит — левая клетка.
Клетка `(x − xmin) >> сдвиг`. У всех заводских: один вход, один
прямоугольник, растр со сдвигом 12.

**Проверка с двух концов:** все 707 тыс. точек `XY` всех 14 таблиц лежат в
закрашенных клетках — в том числе у NO, где закрашено 21 % клеток.
Отвергнуто: Y сверху вниз — до 40 066 промахов; биты от старшего — 251…926.

### Реестр `EJ211_global.tlt` — разобран и сверен с файлами

Блок `OV`, данные с `+0x18`:

| Смещение | Что |
|---|---|
| `+0` | `10 02` |
| `+2` | u16BE число таблиц |
| `+4` | u32BE → пул строк: u16BE число, строки u8 длина + байты; **строка 0 пустая, номера с 0**, повторы хранятся один раз |
| `+8` | записи по 36 байт |

Запись: `+0` u16 строка имени файла, `+2` u16 строка версии (`LUX_3.0`),
`+4` ISO, `+6` ECC, `+7` CC, `+8` LTN, `+9` три байта (у всех `10 E0 18`,
не установлено), `+0xC` i32BE×4 рамка — **в точности прямоугольник `BR`**,
`+0x1C` язык, 2 байта 0, `+0x20` u32BE → каталог блоков.

Каталог: u16BE число блоков (4), u16 `0x0C00`, по 12 байт: u32BE смещение в
файле, u32BE размер с заголовком, u16 строка метки, u16 0.

**Проверка:** все 56 блоков 14 таблиц совпали со смещениями, размерами и
метками в файлах, блоки встык до последнего байта файла. Рамка = охват
точек `XY` ± 15 000 единиц (почти везде ровно; где шире — причина не
установлена).
