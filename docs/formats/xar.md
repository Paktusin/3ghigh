# Архив стилей карты `.xar`

`pkgdb/StyleDBMMI3G_ECE_94/MMI3G_MapArchive_H_04_01.xar`, 4 932 124 байт. На машине
ссылка `/HBpersistence/navi/db/MMI3G_MapArchive.xar` →
`/database/map/styles/01/MMI3G_MapArchive_H_04_01.xar` (шаблон в прошивке
`/database/map/styles/%02d/MMI3G_MapArchive_%c_%02d_%02d.xar`). От покрытия не
зависит, в образ переносится как есть. Здесь — что в нём лежит и **как по нему
красится GDB**: по каким классам какие цвета, где пороги масштаба, какие значки у
категорий POI.

Инструмент: `src/xar.js` (тест `src/xar.test.js`).

```
node src/xar.js <файл.xar>                 разделы, таблица 44 масштабов
node src/xar.js <файл.xar> --areas [night] стили площадей по классам GDB
node src/xar.js <файл.xar> --lines [night] стили линий по классам GDB, правила line0…4
node src/xar.js <файл.xar> --tree [путь]   дерево свойств, путь — имена через /
node src/xar.js <файл.xar> --icons out/styles [кат…]  значки POI в PNG
node src/xar.js <файл.xar> --bitmap out/styles <номер…>  любой растр в PNG
```

## Шапка и разделы — проверено

```
+0x00  'rax\0'
+0x04  u32  0x00010000           версия
+0x08  u32  0x18c3fe86           ? (контрольная сумма — догадка, не проверялась)
+0x10  u32  длина файла          (4 932 124 — сходится)
+0x1c  u32  число разделов (12)
+0x20  u32 × n  смещение раздела в СЛОВАХ (×4 от начала файла)
```

| раздел | смещение | размер | что |
|---|---|---:|---|
| `drx` | 0x50 | 3 412 680 | 730 растров |
| `dpx` | 0x341318 | 295 408 | дерево свойств: 2225 узлов |
| `XPF ` ×9 | 0x389508… | 7 808…498 912 | шрифты `Hi_SignFont`, `Hi_MapStreetSignSmall`, `Hi_MapCityFont`, `Hi_MapStreetFont`, `Hi_MapStreetCoronaFont`, `Hi_MapCityFont50kplus`, `Hi_HMISignFont`, `Hi_IZFont`, `Hi_MapCityBigFont` (поля big-endian, длина по +8) — не разбирались |
| `xg3d` | 0x4abe90 | 33 676 | 3D-модель `Fadenkreuz` (перекрестье) — не разбиралась |

Архив 3G+ (`StyleDBMMI3GP_ECE_9129/…_H_06_01.xar`) читается тем же кодом; цвета
суши в нём те же.

Отвергнуто: «смещения разделов — от 0x3c» (первое смещение 0x14 дало бы 0x50, но
второе 0xd04c6 + 0x3c не попадает ни на какую границу); верно — ×4.

## `drx`: растры — проверено на всех 730

```
'drx\0', u32 0x00010000, u32 0, u32 5, u32 0, u32 n (730)
n × u32 номер (1…730), n × u32 смещение в словах от начала раздела
```

Растр `2MIX`:

```
+0x00 '2MIX'   +0x04 u32 длина   +0x08 u16 w   +0x0a u16 h   +0x0c u32 0x1c
+0x10 u32 смещение блока альфы от начала растра (0 — альфы нет)
+0x14 u32 0    +0x18 u32 0
+0x1c u32 длина блока цвета (считая это слово), +0x20 u32 формат: 0x01072000 (710 шт.)
      или 0x01052000 (20 шт., все без альфы)
+0x24 RLE по словам: n со старшим битом — (n & 0x7fffffff) слов как есть,
      иначе одно следующее слово n раз. Слово — байты B, G, R, x.
блок альфы: u32 длина, u32 0x108, RLE по байтам: c & 0x80 — (c & 0x7f) байт как есть,
      иначе следующий байт c раз.
```

**Сжатия zlib нет** (первое впечатление «2MIX — zlib» неверно). Проверка с двух
концов: у всех 730 растров RLE цвета даёт ровно w·h точек и кончается ровно на
`0x1c + длина блока цвета`; у всех 710 с альфой RLE альфы даёт ровно w·h.
Отвергнуто для альфы: литерал `c − 0x7f` / повтор `c + 1` (сходится у 4 из 730),
литерал `c & 0x7f` / повтор `c + 1` (24 из 730). Порядок B, G, R — по коду
(`FUN_08d1e4e4`: выходной байт 0 = бит 16…23 слова) и по картинке: значок Shell
красно-жёлтый, BP зелёный, вода `#8BBDCD` голубая.

## `dpx`: дерево свойств — проверено

Смещения узлов — от начала раздела **+ 4** (сразу за `'dpx\0'` лежит корень).

```
+0  u32 хеш имени      +4 u16 вид      +6 u16 длина данных
+8  u32 следующий брат +12 u32 первый ребёнок      +16 данные (выровнены до 4)
вид 0 — ветвь; 1 — u32; 2 — строка (шрифты: "14 0 0 Hi_SignFont");
вид 3 — массив u32, первое слово — число слов (у всех 1598 узлов сходится с длиной)
```

Имя — только хеш `h = h·37 + байт` (`FUN_08d1dd98`); `*` = 42. Имена
восстановлены перебором строк прошивки и шаблонов `poi%d`, `sub%d`, `height%d`,
`line%d`, `streetsign%d`…: из 2225 узлов без имени осталось 145. Дети записаны
в обратном порядке (добавлялись в голову списка).

**Поиск** (`FUN_08d1dc68`): путь — массив хешей; на каждом шаге берётся ребёнок с
нужным хешем, при неудаче — ребёнок `*`, который **поглощает один или больше**
элементов пути; на последнем элементе `*` не подставляется. Путь из 7 элементов:

```
[вид карты, день/ночь, 2d/3d, раздел, ?, объект, свойство]
mainMap / day|night / 2d|3d / area|line|poi|route|… / * / water|frc4|poi56 / rendering|naming|sub0
```

Элемент 4 обработчики не задают (в данных там всегда `*`). Корневые ветви:
`mainMap`, `hmi`, `jv`, `#c88832f5`, `#a7a0b00d`, `#4a7b27d0`, `#bffb58a6`.

## Площади: класс GDB → стиль — проверено по коду

`getAreaStyle(attrib, height)` (`FUN_09272200`): ассерт `attrib.form == 5`
(`ElementForm_TriangleSet`); при `height == 0` индекс стиля =
`attrib.m_class[1] − 0x10`, за пределами 0…15 — последний стиль (17-й,
`unknown`) с сообщением `unexpected attrib.m_class[1]`. `m_class[1]` — класс
GDB: дамп тайла печатает его по таблице `GDB_FRC0 … GDB_LAND` (`0x09a5f208`), и

рисуется так же, как заводская кипрская `0x5D`; менять не нужно.

Запись стиля площади — 8 слов: `от, до, заливка BGRA, цвет 2 (обычно 0xFF000000),
флаги, ?, цвет 3, текстура`. Флаги (`FUN_0927d974`): бит 3 — текстура по полю 7,
биты 0, 1, 2, 4 — что-то булево. Альфа 0 в заливке = площадь не видна на этих
масштабах (лес и парки при индексе ≥ 23). Цвет 2 и флаги на рисунок суши не
влияют — значения у всех земель одинаковые.

### Ступени рельефа (0x60)

`getAreaStyle` с ненулевой высотой: таблица `area/*/*/heights` = 40 100 200 500 700
1000 1500 2000 3000 4000 5000, стиль = первый `i`, где `высота·10 < heights[i]`,
при выходе за таблицу — последний (10). Если в функцию приходит ступень `s` из
бит 8…19 атрибута (единица 10 м, docs/formats/gdb.md), заводские ступени
ложатся так: 4 → `height1`, 10 → 2, 20 и 30 → 3, 70 → 5, 100 → 6, 150 → 7, 200 → 8,
300 → 9, 400…600 → 10. **Догадка:** что второй аргумент — именно `s`, в коде не
прослежено (вызывающий не найден). Днём у `height1…11` на индексах 0…22 альфа 0 —
**тонировка рельефа видна только при отдалении, индекс масштаба ≥ 23** (6200 и
дальше); `height0` совпадает с сушей.

Ширины уменьшаются с индексом масштаба (полная таблица — `--lines`). Запись
линии — 20 слов: `от, до`, внутреннее перо `флаги, ширина, цвет, цвет 2`, 2 слова,

`FUN_092695e0` раскладывает значение на поля: биты 0–2 FRC, 3–5, 6, 7, 8, 9, 10–11,

бите 7 → `line0…3` (те же ширины, приглушённые цвета), бит 9 → `line4` (кайма
`#CD0000`). Какие биты атрибута GDB становятся этими полями — не прослежено.

## POI: категория → значок — проверено

`poi/*/poi<N>/sub<M>` (`FUN_09272bc4`; список пар — `typespoisub`, 91 пара).
**N — номер категории LIT** (поле `0x4f`, номер в таблице `NAVRESOURCE XAC` с
единицы, docs/formats/lit.md). Сверено картинкой на шести категориях:

| N | категория LIT | значок |
|---:|---|---|
| 2 | `AUTOBAHN-KNOTEN` | развязка |
| 20 | `BEHÖRDE` | здание |
| 43 | `APOTHEKE` | зелёный крест |
| 45 | `POLIZEIWACHE` | полицейский |
| 46 | `RESTAURANT` | вилка и нож |
| 56 | `TANKSTELLE` | колонка; `sub1…18` — бренды: Aral, Avia, BP, OMV, Q8, Shell… |

`sub` — подкатегория (у заправок — бренд); откуда она берётся в записи LIT — не
прослежено. Запись значка — 19 слов: `от, до, ширина, высота, номер растра, …`;
номер растра — номер в `drx`. Значки 16×16, показываются на индексах 0…23.
Есть стили и для `N > 192` (`poi242` — значок места отдыха): это не таблица
`NAVRESOURCE`, источник не установлен.

## E0 элемента GDB — не установлено, догадка

Байт после `E0` в потоке тайла кладётся в `+9` итератора (`FUN_08cb3f90`) и
переносится в байт `+1` записи элемента (`FUN_08cb3d8c`). Ни в обработчиках стиля,
ни в `isVisibleForScale` (`0x0927dc40`: «видим, если у стиля есть запись на текущий
индекс») он не читается. Значения у завода (здания 4, улицы 8, лес 20, крупные
города 22, автомагистраль 24, крупные озёра 34, границы 40, море/суша 0xFF) лежат в
том же диапазоне 0…43, что и индексы масштаба, и растут с «важностью» —
**догадка:** верхний индекс масштаба, до которого элемент показывается (0xFF —
всегда). Порядком отрисовки он не является: малые озёра (E0 18) идут в тайле после
леса (E0 20). Проверки кодом нет; наши значения взяты в заводских пределах, менять
их по стилям нечем.

## Что это меняет для GDB (src/gdbgen.js, src/osmareas.js)

* Суша: `0x5F` (`LAND_FC`) и заводская кипрская `0x5D` (`LAND_MAPINFO`) красятся
  одинаково — **менять не нужно**.
* `0x57` — не «перрон», а `GDB_LANDEBAHN` (стиль `runway`, серый `#D5D5D5`).
  Под него идут `aeroway=runway` (площадью) — сейчас пишем туда `aeroway=apron`,
  по цвету это то же серое покрытие.
* `0x55` — здания (`GDB_GEBAEUDE`), видны только на индексах 0…2; догадка из
  gdb.md подтверждена.
* Найдены классы, которых мы не пишем: `0x58` пешеходная зона, `0x59` транспортная
  площадь, `0x5A` остров, `0x5B` больница (`#EE9473`), `0x5C` кладбище (`#A4BDAC`) —
  кладбища теперь есть куда класть (`landuse=cemetery` → `0x5C`).
* Линии: класс 9 — `GDB_FLUSS` (река), 10 — `GDB_KANAL`; стиль у обоих один,
  поэтому рисуется одинаково, но реки по смыслу — 9. «Класс 9 вдоль B16 на L3…L10»
  из gdb.md — почти наверняка Дунай, идущий вдоль B16, а не дорога.
* Ступени рельефа видны только при индексе масштаба ≥ 23; ступени 20 и 30
  красятся одним стилем (`height3`).
